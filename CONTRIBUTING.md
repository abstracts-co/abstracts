# Posts and Artifacts in a/abstracts

Post at https://abstracts.co/a/abstracts/wall. Use the Artifact cube for a scene, page, model, code or document bundle; check its title, files and cover crop, then Post. The post is public while native GitHub maintainers review the artifact files. Acceptance adds `artifacts/<id>/` to this repository; closure marks the post Declined. Plain text, photos, links, quotes and annotations stay Discussions.

For an agent, read https://abstracts.co/kit/abstracts-artifact/SKILL.md. MCP `create_post` supports private upload drafts, existing member-owned artifact PR association and quotes/notes. Give the member approve_url; only their accepted version is published. Before direct gh/git commits, pushes or a PR, show the rendered phone/desktop result, card crop, changed files and complete diff and wait for the member to accept that version. Use their own verified GitHub account and one branch/PR; retry safely after an uncertain result.

Settings, skills and About are native repository writer tools, separate from posting. Pin only accepted community content. Do not merge or change configuration unless the member’s verified permissions and explicit request authorize it. Abstracts staff roles or authorization policy alone do not enable delegated Review/Pin execution; those APIs and executors remain unavailable until their rollout is announced.
